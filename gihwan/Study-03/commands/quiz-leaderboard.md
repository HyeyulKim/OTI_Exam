# 퀴즈 순위 시스템 관리

`Study-03/script.js`의 랭킹 로직과 브라우저 `localStorage`의 `normalization-quiz-ranking` 데이터를 검사하고 관리한다.

## 검사 대상

- 랭킹 기록의 닉네임, 점수, 총 문항 수, 생성 시각
- 점수와 총 문항 수의 유효성
- 점수 비율 기준 정렬 여부
- 동률 시 점수와 기록 시각에 따른 순서
- 최대 10개 기록 제한
- 빈 닉네임 또는 중복·손상 기록
- 메인 화면과 결과 화면에서 같은 랭킹 데이터를 표시하는지 여부

## 순위 기준

현재 게임의 순위 기준을 다음 순서로 확인한다.

1. `score / total` 점수 비율 내림차순
2. 점수 비율이 같으면 원점수 내림차순
3. 모두 같으면 먼저 기록된 순서

순위 기준이 코드와 저장 데이터에서 다르면 불일치로 보고한다. 점수 비율을 계산할 수 없는 기록은 정상 순위에 포함하지 말고 별도 손상 기록으로 표시한다.

## 관리 작업

사용자의 요청이 있을 때만 다음 작업을 수행한다.

- `조회`: 현재 유효한 랭킹을 순위와 함께 출력한다.
- `검증`: 기록 구조, 정렬, 최대 10개 제한, 화면 연결을 확인한다.
- `정리`: 손상된 기록만 제거 대상으로 제안한다. 자동 삭제는 사용자가 명시적으로 요청한 경우에만 한다.
- `초기화`: 모든 랭킹 삭제는 사용자가 명시적으로 요청한 경우에만 수행하며 실행 전에 확인한다.
- `내보내기`: 닉네임, 점수, 총 문항 수, 기록 시각을 표 형태로 출력한다.

`$ARGUMENTS`가 없으면 `조회`와 `검증`을 수행한다. `$ARGUMENTS`가 있으면 위 작업명으로 해석한다.

## 출력 형식

```text
## 랭킹 상태
- 저장 키: normalization-quiz-ranking
- 전체 기록: 숫자
- 유효 기록: 숫자
- 손상 기록: 숫자

## 순위
1. 닉네임 - 점수/총 문항 수 (점수 비율)
2. 닉네임 - 점수/총 문항 수 (점수 비율)

## 검증 결과
- 정렬 기준: 정상 | 불일치
- 최대 10개 제한: 정상 | 위반
- 메인 화면 표시: 정상 | 확인 필요
- 결과 화면 표시: 정상 | 확인 필요

## 관리 의견
- 정리 또는 확인이 필요한 내용
```

## 실행 지침

1. `Study-03/script.js`에서 저장 키와 `loadRanking`, `saveRanking`, `renderRanking` 동작을 확인한다.
2. `localStorage`의 랭킹 데이터를 읽을 수 있으면 JSON 배열인지 확인한다.
3. 각 기록의 점수와 총 문항 수를 검증하고 점수 비율을 계산한다.
4. 현재 코드의 정렬 기준과 실제 기록 순서를 비교한다.
5. 손상 기록은 원문과 원인을 표시하고, 사용자 승인 없이 삭제하지 않는다.
6. 조회와 검증은 데이터를 변경하지 않는 읽기 전용 작업으로 수행한다.
